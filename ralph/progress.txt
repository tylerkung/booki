## Codebase Patterns
- Supabase migrations use sequential numbering: `028_push_notification_tables.sql` is the next available
- Always use `IF NOT EXISTS` for tables and indexes in migrations
- RLS policies follow pattern: "Users can {verb} own {table}" with `auth.uid() = user_id`
- No local Supabase for lint — migration SQL validated manually
- No local Deno — typecheck validated by following existing _shared/ patterns
- Shared helpers use `createServiceClient()` for service-role DB access
- `sendNotification()` is fire-and-forget — import from `'../_shared/notifications.ts'`
- APNs JWT uses WebCrypto ECDSA P-256 (importKey pkcs8), cached 50 min

## CRITICAL: iOS App is the Reference Implementation
- **Always read the iOS Swift code before building web equivalents.** The iOS app is the source of truth for how features work, what edge functions expect, and how data flows.
- **Edge function payloads:** Read the iOS service files (`BetService.swift`, `EdgeFunctionService.swift`, etc.) to see exact payload shapes sent to edge functions. Do NOT guess field names or values.
  - `submit_bets` expects `side: 'a'` or `'b'` (side_indicator), NOT human-readable names like "Lakers ML"
  - `submit_parlay` expects `side_indicator: 'a'` or `'b'` per leg, plus `side` as human-readable
  - Both require `player_id`, `bookie_id`, `idempotency_key` at top level
- **Balance convention:** Internal positive = player owes bookie. Player-facing display NEGATES this. iOS uses `BalanceService.playerSummary()` which includes open stakes in credit utilization.
- **Credit calculation:** Available credit = credit_limit - max(0, balance) - open_stakes. Do NOT use Math.abs(balance) — winning players (negative internal balance) should NOT have reduced credit.
- **Player name updates:** RLS on players table requires `is_bookie()` — players CANNOT directly update their own record. iOS uses `claim_player` edge function pattern. Web must use an edge function too.
- **Key iOS reference files for web parity:**
  - `Booki/Services/BetService.swift` — bet submission payloads
  - `Booki/Services/BetSlipManager.swift` — bet slip selection model
  - `Booki/Services/BalanceService.swift` — balance and credit calculations
  - `Booki/Services/SettlementService.swift` — settlement report logic
  - `Booki/Views/BetSlipSheet.swift` — bet slip UX flow
  - `Booki/Views/TrackView.swift` — ticket grouping and display
  - `Booki/Views/PlayerMainView.swift` — player tab structure
