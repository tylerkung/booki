## Codebase Patterns
- BookieTier enum is in Bookie.swift (not a separate file) — legacy `.default`/`.chart` preserved for migration compatibility
- SyncService has two bookie sync methods: `downloadBookieForPlayer` (for player accounts) and `refreshBookieSettings` (for bookie accounts) — both must be updated when adding bookie fields
- BookieRecord in BookieService.swift is the Codable DTO for Supabase — add new columns here with CodingKeys mapping
- SwiftData `#Predicate` doesn't work reliably with enum comparisons — fetch with simpler predicate then filter in-memory
- TierService provides `@AppStorage`-backed tier cache via `TierService.currentTier` / `TierService.isPro` for instant UI reads
- Use `BookieTier.isPro` for tier checks instead of comparing to specific enum values (future-proofs for new tiers)
- New .swift files need manual pbxproj entries: PBXBuildFile, PBXFileReference, Views group children, and Sources build phase
- ProUpgradeSheet accepts optional `contextMessage: String?` — pass context-specific upsell text from each entry point
- Bookie Settings is SettingsView.swift; Player Account is AccountView.swift — don't confuse them
- Settings row layout: HStack(spacing: 14) with icon (20pt, accent, 28w frame) + title + Spacer + value + chevron, padded (.horizontal 16, .vertical 14)
