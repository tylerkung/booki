## Codebase Patterns
- Use `IF NOT EXISTS` for all CREATE TABLE and CREATE INDEX statements in migrations
- All tenant-isolated tables must have `bookie_id` column with index
- Use DECIMAL(15, 2) for money amounts in PostgreSQL
- Use TIMESTAMPTZ (not TIMESTAMP) for all date/time fields
- Include updated_at triggers for tables that track modification time
- SQL migrations go in `supabase/migrations/` directory
- RLS helper functions use SECURITY DEFINER for consistent permissions
- RLS policies use double-check pattern: `is_bookie() AND bookie_id = get_user_bookie_id()`
- Players authenticate via auth_user_id linkage, not username/password in app
- Use `fetchOrCreateBookie()` pattern for idempotent bookie record creation
- AuthManager handles bookie record lifecycle via auth state listener (signedIn event)
- Supabase Codable models use CodingKeys for snake_case database columns
- Download sync uses dependency order: players first (for relationships), then events, bets, etc.
- Upsert logic compares server.updatedAt > local.lastSyncedAt to decide if update needed
- Ledger entries are append-only - skip updates, only insert new records
- Use pagination (range from:to:) for tables that may have many records (limit 1000)
- Upload sync uses same dependency order as download: players first, then events, bets, etc.
- Use `onConflict: "id"` in Supabase upsert for proper update-or-insert behavior
- Version-based conflict detection: query server version before upload, abort if server > local
- Use NotificationCenter for sync conflict notifications to UI layer
- Upsert structs need `init(from:bookieId:)` to convert SwiftData models
- Failable initializers (init?) for upsert structs that require relationships
- Realtime subscriptions use `supabase.realtimeV2.channel(tableName)` with `postgresChange(AnyAction.self, ...)`
- Subscribe to realtime AFTER initial sync completes to avoid duplicate processing
- RLS automatically filters realtime events - no manual bookie_id filtering needed in subscription
