## Codebase Patterns
- Web dashboard uses Alpine.js (`x-data`, `x-show`, `x-cloak`, `x-for`, `x-text`, `@click`) with Supabase JS client
- Routes are hash-based (`#/events`, `#/members/{id}`) parsed in `parseRoute()` — add new routes to the `routes` array
- Sidebar nav links in `app.html` between `<ul class="sidebar-nav">` tags
- Views are `x-show="route === 'xxx'"` sections inside `<main class="main-content">`
- Use existing CSS classes: `.card`, `.card-header`, `.card-title`, `.chip`, `.chip.active`, `.badge`, `.badge-muted/warning/success/danger`, `.data-table`, `.search-input`, `.filter-bar`, `.empty-state`, `.shimmer`
- Events are shared (bookie_id IS NULL) — use `.is('bookie_id', null)` in Supabase queries
- Sport DB values: `americanfootball_nfl`, `basketball_nba`, etc. — use `formatSportName()` for display
- State variables go at the top of `dashboardApp()`, methods below `init()`
- Computed getters use `get` syntax for Alpine reactivity
- Edge functions called via `callEdgeFunction(name, body)` — always include `idempotency_key: crypto.randomUUID()`
- Modals placed outside `<template x-if>` blocks to survive re-renders — at the view section level
- The `allBets` query in `loadDashboard()` must include ALL columns used by `computeAttentionTags()` — add new columns to `.select()` when tags depend on them
- Pro-gated pattern: `.pro-gated-section` card + `pro-blur` class + `.pro-upgrade-overlay` overlay
- Dual-role auth: `userRole` is 'organizer'|'player'|'standalone'. Player routes prefixed with `player-`. Organizer data only loads for organizer role.
- Player state: `playerId`, `playerBookieId`, `playerRecord` (full player row), `playerBookie` (organizer's bookie settings)
- Sidebar links use `x-show="userRole === 'organizer'"` or `x-show="userRole === 'player' || userRole === 'standalone'"`
- Player games: markets lookup via `playerMarketsByEvent` computed getter (nested map: event_id → market_type → market object) for O(1) access in templates
- Bet selections stored in `betSlipSelections[]` with `event_id`, `market_id`, `side`, `side_indicator`, `odds`, `event_name`, `market_type`
- Bet slip submission: `submit_bets` for singles (partial success model), `submit_parlay` for multi-picks (combined_odds as American number)
- American↔decimal odds: positive → `1 + odds/100`, negative → `1 + 100/abs(odds)`. Multiply decimals for parlay combined odds
- CSS namespacing: `pg-` for player games, `bs-` for bet slip — prevents class collisions
