## Codebase Patterns
- Dashboard SPA uses Alpine.js with hash-based routing in `landing/dashboard/dashboard.js`
- Routes parsed via `parseRoute()` on `hashchange` events — use regex for parameterized routes
- State variables (e.g. `selectedPlayerId`) live in the Alpine data object returned by `dashboardApp()`
- Edge functions called via `callEdgeFunction(name, body)` helper with auth headers
- Player data cached in `playerMap` (keyed by id) for O(1) lookups
- `allLedgerEntries` stores all ledger entries (with type/created_at) for per-player analysis (tags, overdue detection)
- `allBets` query in `loadDashboard` includes `player_id, bet_type, created_at` — use for per-player grouping
- Loading skeleton pattern: `template x-if="isLoadingX"` with shimmer divs, `template x-if="!isLoadingX"` with real content
- Responsive table-to-card: add `data-label` attrs to `<td>` elements, CSS `::before` with `content: attr(data-label)` for labels
