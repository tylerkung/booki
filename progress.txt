## Codebase Patterns
- project.pbxproj has 4 build configuration sections: Debug (project), Release (project), Debug (target), Release (target). Each has its own IPHONEOS_DEPLOYMENT_TARGET and SWIFT_VERSION.
- supabase-swift package uses `upToNextMajorVersion: 2.0.0` — no change needed for iOS 26 migration
- Xcode IDE required for full builds — command-line can't verify typecheck (per CLAUDE.md)
- Tab API: Use `Tab("Title", systemImage: "icon") { content }` (no selection) or `Tab("Title", systemImage: "icon", value: N) { content }` (with selection binding). `.badge()` goes on the Tab.
- @Observable singletons (.shared): Replace `@ObservedObject private var x = X.shared` with `private var x = X.shared` — SwiftUI tracks access automatically.
- Swift 6 strict concurrency: All @Observable classes need @MainActor. Non-actor service singletons with only `let` properties use `@unchecked Sendable`. Error enums with `Error` associated values need `@unchecked Sendable`. Closure params crossing isolation boundaries need `@Sendable`.
- `callFunction(body: Encodable)` changed to `body: some Encodable & Sendable` — all request types are structs with value-type properties (auto-Sendable).

- **Learnings for future iterations:**
  - In Swift 6, `SWIFT_STRICT_CONCURRENCY = complete` is redundant with `SWIFT_VERSION = 6.0` (strict concurrency is the default in Swift 6), but adding it explicitly documents intent
  - All @Observable classes MUST have @MainActor since they hold UI state — without it, property access from SwiftUI views has no isolation guarantee
  - Final classes with only `let` properties are effectively immutable and safe to mark `@unchecked Sendable`
  - Error enums with `Error` (non-Sendable protocol) associated values need `@unchecked Sendable` — the concrete error types (URLError, DecodingError) ARE Sendable but the existential isn't
  - Existential `Encodable` parameter crossing actor boundaries is non-Sendable; use `some Encodable & Sendable` for opaque type
  - `Task.detached { [weak self] in }` where self is @MainActor: Swift 6 region-based isolation (SE-0414) allows this because all access goes through actor-hopping
  - Xcode IDE required for build verification — command-line xcodebuild needs `sudo xcode-select -s` to switch developer directory
