## Codebase Patterns
- SQL migrations follow style in `006_audit_events.sql`: CREATE TABLE → indexes → RLS → policies → COMMENTS
- Payout math (American odds): win positive = -(stake * odds/100), win negative = -(stake * 100/abs(odds)), loss = +stake, push/void = 0
- Internal balance convention: positive = player owes bookie, negative = bookie owes player
- Edge functions use service role for DB writes; RLS policies are SELECT-only for most financial tables
- Immutability triggers on ledger_entries, settlement_events, audit_events prevent UPDATE/DELETE
- settle_bet_tx RPC is SECURITY DEFINER — callable via `.rpc('settle_bet_tx', { params })`
- RPC functions return `{ success: false, error }` for business rule violations (not Postgres errors) — check `data.success` after `rpcError`
- Edge function RPC refactor pattern: keep CORS + JWT + idempotency + ownership check, replace inline DB ops with single RPC call
