## Codebase Patterns
- SQL migrations go in supabase/migrations/ with format NNN_description.sql
- Use `IF NOT EXISTS` for all CREATE TABLE and CREATE INDEX statements
- RLS policies follow naming pattern: `tablename_action_description`
- Document all migrations in SUPABASE_MIGRATIONS.md under "Completed Migrations"
- auth.uid() is used for RLS policies to reference current authenticated user
- Edge Functions go in supabase/functions/<function-name>/index.ts
- Shared Edge Function utilities in supabase/functions/_shared/
- Use `https://esm.sh/@supabase/supabase-js@2` for Deno imports
- Edge Functions access env vars via Deno.env.get('VARIABLE_NAME')

## 2026-01-27 - US-009
- **What was implemented**: Supabase Edge Functions infrastructure with shared utilities
- **Files changed**:
  - Created: supabase/functions/_shared/cors.ts (CORS headers constant)
  - Created: supabase/functions/_shared/supabase.ts (createServiceClient, createUserClient, getUserIdFromAuthHeader helpers)
  - Created: supabase/functions/README.md (documentation and deployment instructions)
- **Learnings for future iterations:**
  - Edge Functions use Deno runtime with ESM imports from https://esm.sh/
  - CORS headers must be included in all responses for iOS app to communicate with functions
  - createServiceClient() uses SUPABASE_SERVICE_ROLE_KEY to bypass RLS
  - createUserClient() uses the user's JWT token to respect RLS
  - getUserIdFromAuthHeader() extracts user ID from JWT by calling client.auth.getUser()
  - Deno is not installed locally; typecheck happens during Supabase deployment
  - All mutation functions should use idempotency_key pattern to prevent duplicate operations
  - Idempotency keys table stores: key (client-provided), operation (function name), response (cached JSON), user_id, expires_at
  - submit_bet validates: player ownership, event existence, event not locked (status != locked AND start_time > now)
