## Codebase Patterns
- PlayerClaimView uses Supabase directly for invite code validation (not local SwiftData) because players don't have local data when claiming
- When updating Supabase tables directly, use snake_case for column names (e.g., `auth_user_id`, `claimed_at`)
- Always create a Codable struct with CodingKeys for Supabase responses that use snake_case

- AuthManager.ensureBookieRecord() checks for player record FIRST via auth_user_id, then falls back to bookie record
- currentPlayerId is the player.id from the players table, not the auth_user_id

- PlayerDetailView is defined INSIDE PlayersListView.swift, not a separate file
- For direct Supabase deletes, delete child records (bets, ledger_entries) BEFORE the parent (player) due to foreign key constraints

- AddPlayerInterstitialSheet uses a binding to trigger AddPlayerSheet after dismissing via DispatchQueue.main.asyncAfter delay
