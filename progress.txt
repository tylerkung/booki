## Codebase Patterns
- Edge Functions use Deno runtime - `tsc` reports false errors for Deno imports/globals; the baseline errors (`.ts` extension imports, `Deno` not found, `req` implicit any) are expected and shared by all Edge Functions
- Always normalize UUIDs to lowercase with `.toLowerCase()` before DB operations (iOS sends uppercase, PostgreSQL stores lowercase)
- Use `Array.from(new Set(...))` instead of spread `[...new Set(...)]` for Set iteration in Edge Functions to avoid downlevelIteration errors
- Audit ActionType must include all action types used across Edge Functions: `bet_submitted`, `bet_auto_accepted`, `bet_auto_graded`
- Events can be shared (bookie_id = NULL) or bookie-specific; validate with `event.bookie_id !== null && event.bookie_id !== requestBookieId`
- All Edge Functions follow the pattern: CORS -> JWT auth -> validate input -> idempotency check -> business logic -> audit event -> store idempotency -> return response
