## 2026-01-29 - US-001
- **What was implemented**: Fixed duplicate team display when both moneylines are selected on the same game
- **Files changed**: Booki/Views/BetSlipSheet.swift
- **Root cause**: ForEach was using `\.element.marketId` as id, but two moneyline selections (e.g., Hawks ML and Rockets ML) share the same marketId
- **Fix**: Changed ForEach id from `\.element.marketId` to `\.element` (the BetSlipItem itself), which uses Hashable including eventId + marketId + side
- **Learnings for future iterations:**
  - When ForEach shows duplicate/incorrect items, check the id parameter - it must uniquely identify each item
  - BetSlipItem's Hashable implementation includes `side` specifically to distinguish different sides of the same market
  - Two selections on the same market (both sides of ML) are intentionally allowed by the app design

## 2026-01-29 - US-002
- **What was implemented**: Fixed bet submission error by using correct side parameter format for Edge Function
- **Files changed**: Booki/Views/BetSlipSheet.swift, Booki/Views/SubmitBetView.swift
- **Root cause**: BetSlipSheet and StakeEntryView were passing `item.side` (team name like "Hawks") to submit_bet Edge Function, but the function expects `side` to be 'a' or 'b'
- **Fix**:
  - BetSlipSheet: Changed `side: item.side` to `side: item.sideIndicator`
  - SubmitBetView: Added `sideIndicator` field to `BetSelection` struct
  - SubmitBetView: Pass `sideIndicator` when creating BetSelection in continueButton
  - StakeEntryView: Changed `side: selection.side` to `side: selection.sideIndicator`
- **Learnings for future iterations:**
  - Edge Functions validate input strictly - submit_bet requires side as 'a' or 'b', not team names
  - BetSlipItem has `side` (display) and `sideIndicator` (server) - always use `sideIndicator` for server calls
  - BetConfirmationSheet was already correct (used `item.sideIndicator`) - can reference as example
  - When adding new models that pass data to servers, include both display and server-format fields
