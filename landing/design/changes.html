What changed

Booki design system · August 2026

Every comparison below is live. The before panels simply re-declare the tokens as they were — which is only possible because the fixes went into the token layer rather than into individual rules. Anything that needed a screenshot to demonstrate would not have been a systemic fix.

1 · Tracking

Inter ships loose. Booki was already correcting for it — -0.02em appeared in ten places — but as eight raw values across two unit systems. That mix was the defect: px tracking does not scale with font size, so the same 0.5px meant 0.045em on an 11px label and 0.036em on a 14px one. Same intent, different result depending on where it landed.

2 · Numerals

Two separate problems, two different treatments. Tabular figures everywhere numeric, because proportional digits are drawn at different widths — a balance ticking from 1,180 to 1,220 visibly shifts, and a column of stakes never aligns. Monospace only for odds and scores, which are machine data read in columns. Money keeps the product's own typeface: a balance is the member's own figure.

3 · Motion

The defect was easing, not duration. --ease was defined as the literal keyword ease and referenced zero times, so all 66 transitions fell through to the CSS default — which is also ease, a curve that accelerates before settling. Every hover in the product started slowly, which contradicted the system's own anti-patterns page.

After · 0.12s, damped

Hover both. The right one leaves immediately and settles; the left hesitates first. One curve — cubic-bezier(0.22, 1, 0.36, 1) — was already in the codebase on four marketing scroll reveals and had never reached the product.

4 · Focus

The design system specified “2px accent, 2px offset, on every interactive element” from the day it was written. The product had 60 hover states and zero focus states — all three :focus-visible rules that existed lived inside the design system's own documentation page, and --shadow-focus was referenced nowhere at all.

5 · Contrast

Seven --fill-*-foreground tokens now pair every tinted fill with the text colour legible on it, so a new badge cannot be built wrong. The convention is borrowed from shadcn/ui; the values are Booki's.

6 · Twelve dead media queries

Found while consolidating components, and the largest single bug of the work.

@media (max-width: var(--w-content)) is invalid CSS. It does not throw, does not warn, and renders in DevTools exactly like a working rule. It simply never matches, at any width. Custom properties are resolved per element at computed-value time; a media condition is evaluated before any element exists.

Twelve of these existed in dashboard.css, holding 66 rules between them — the sidebar, the mobile header, the stats grid and the entire data-table card transform. The dashboard's mobile layout had been inert.

The mistake is invisible precisely because the codebase is disciplined: every other value routes through a token, so writing var() in a media query is what consistency looks like. check-design-tokens.py even allowed raw px in an @media line for this reason — that allowance and the missing check were two halves of one rule, and only the first half existed.

7 · Components

Phase 4 assumed 465 classes meant heavy duplication. Measuring found only 10 exact duplicate rule bodies across 21 selectors — for an Alpine SPA with many views, most of those classes are genuinely distinct. So the value was in the specific cases, not a sweep.

Four <select> elements each carried their own inline style attribute, all slightly different, all bypassing the stylesheet — and a native select paints its own OS dropdown arrow, which on a dark interface reads as a foreign control.

After · .select

Also promoted: .progress, consolidating two near-identical bespoke bars, and .tooltip, generalising .tag-tooltip — which was well built and simply named for its one use. Avatar was deliberately not built: nothing renders one, and a component with no caller is a liability that still has to be maintained.

What now enforces this

Every fix above was a rule someone had already written down. None of them failed for lack of documentation — they failed because nothing checked. scripts/check-all.sh now runs eight checks, and each new one was verified by deliberately breaking the thing it guards.

8 · Two loose ends, closed

transition: all appeared 12 times. It animates every property including layout ones, and it hides what a rule is actually doing — .toggle-btn was the clearest case: its active state swaps the background to a linear-gradient, and a gradient is a background-image, which CSS cannot interpolate. It swapped instantly however long the duration said. all made it look animated when it never was. Each of the 12 is now the explicit list of properties its own state rules change.

The breakpoints were subtler than they looked. (max-width: 768px) paired with (min-width: 769px) is not a duplicate — it is a deliberate non-overlapping pair, and it is what most people write. But a viewport can report a fractional CSS pixel width at some zoom levels and on devices with fractional DPR scaling, and 768.5px matches neither. Both sides of the layout switch off at once.
